# dsh-moblie-control

用手机远程操控电脑上的 DSH，让电脑替你干活。

> 干活的是电脑，下命令的是手机。

## 这是什么

DSH（DeepSeek Harness）跑在你的电脑上，能直接使用本机的文件系统、终端和整套工具链，能力远不是手机能比的。但它默认只在本机 `127.0.0.1` 上开一个 Web 界面，人一离开电脑就用不上了。

这个项目想解决的只有一件事：**把电脑上的 DSH 会话安全地接到手机上**。于是你在地铁上、床上、会议室里也能：

- 给电脑上的 DSH 下指令、接着聊
- 实时看它干到哪一步、动了哪些文件
- 对危险操作（删文件、装依赖、跑脚本）当场批准或拒绝
- 电脑端持续执行，手机断线重连后接着看

一句话：**在手机上操控电脑上的 DSH 给你干活。**

## 工作原理（设想）

```
手机浏览器 / PWA
      │  HTTPS + 鉴权
      ▼
电脑上的接入层（局域网直连 / 隧道 / 中继）
      │
      ▼
DSH 的 Web 界面与会话（本机 127.0.0.1，例如 http://127.0.0.1:19387）
      │
      ▼
本机文件系统 · 终端 · 工具链
```

几个关键设计取舍：

- **接入层是关键**。DSH 的 Web 界面默认绑定 `127.0.0.1`，手机直接访问不到，所以必须有个接入层解决「从局域网或公网安全地到达本机回环地址」这件事。
- **手机端先做响应式 Web，不做原生 App**。优先按 PWA 标准做，能装到桌面就够用，省掉一套 App 的开发和分发成本。
- **状态留在电脑上**。手机只是遥控器加显示器，会话、任务、上下文都跑在电脑端。换设备、锁屏、断网都不影响电脑继续干活。

## 安全提醒

手机远程操控电脑，等于把电脑的最高权限交到了手机上，这个项目必须在设计阶段就认真对待：

- 默认只监听局域网，不默认暴露公网
- 强制鉴权，不搞「内网就免密」那一套
- 危险操作在手机上二次确认，不静默执行
- 传输全程加密，访问令牌可随时吊销
